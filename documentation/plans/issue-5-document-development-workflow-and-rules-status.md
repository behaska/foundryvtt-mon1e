## Context
Issue body (fetched via WebFetch, paraphrased): four short documents — `DEVELOPMENT.md` (commands and conventions actually in use), `DECISIONS.md` (technical and functional decisions), `RULES.md` (confirmed vs unknown Mon rules), README. ## 1. Objective
A newcomer can read a short README, find the real commands, see which decisions were taken, and see that no Mon rule is confirmed yet — with every documented command proven to work.

## 2. Scope
### Included
- Ensure `README.md` exists at the repo root (brief section 7), short, linking to the three docs.
- Check `docs/DEVELOPMENT.md`, `docs/DECISIONS.md`, `docs/RULES.md` against reality; fix drift only.
- Run each documented command and confirm it matches the doc.
- Keep all four documents short.

### Out of scope
- Any new Mon rule, rule invention, or filling in `RULES.md` unknowns (needs the Mon author).
- New scripts, CI, linters, Foundry type declarations.
- Data models, sheets, `src/rules` (issue #6+).
- Editing `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.agents/` (generated by `llm sync`).
- Ticking issue boxes (maintainer does it).

## 4. Architecture decisions
- Docs-only change; no code, config or dependency touched.
- Move `docs/README.md` to root with `git mv` (preserves history) and fix its relative links (`docs/DEVELOPMENT.md`, `docs/RULES.md`, `docs/DECISIONS.md`, brief path). Alternative (keep in `docs/`) rejected: GitHub renders root README, and brief places it at root.
- README stays a pointer: what the project is, current state, how to run checks, links. No duplication of DEVELOPMENT.md content.
- `RULES.md` stays honest: no rule added. Only its structure is verified; unknowns stay unknowns.
- Do not duplicate verification evidence across docs; DEVELOPMENT.md keeps its records, optionally condensed.
- Check any Foundry claim against official v14 docs, not memory.

## 7. Expected tests
- Docs are not unit tested. Validation is by running the documented commands: `npm run typecheck`, `npm test`, `npm run check`, single-file `node --test tests/constants.test.mjs` — all exit 0.
- Link check: every relative link in README/docs resolves to an existing file.
- Foundry side: nothing new; runtime load already recorded for #3. Do not claim new Foundry verification.

## 8. Risks and mitigations
- Docs drift from reality → run each command, copy outputs, not memory.
- Inventing a Mon rule or decision reason → forbidden; cite a source file or leave as unknown.
- Docs grow long → trim, link instead of repeat; acceptance criterion requires short.
- Moving README breaks links or external references → `git mv`, grep for `docs/README` and `README.md` references (e.g. in plans) and fix only living docs, not historical plans.
- `CLAUDE.md` (generated) mentions docs layout → leave; if stale, report to maintainer to run `update-context`.

## 9. Stop criteria
- A documented command fails or differs from the doc and the cause is not a docs error: stop, report exact output.
- Task would require inventing or choosing a Mon rule, or Actor/Item types: stop, ask the maintainer / Mon author.
- Fix requires a new script, dependency or Foundry types: out of scope, escalate.
- Brief and issue disagree on README location and the maintainer prefers `docs/`: stop and confirm.
